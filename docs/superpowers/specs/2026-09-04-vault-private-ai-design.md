# Vault + Private AI Design

**Date:** 2026-09-04  
**Status:** Approved design  
**Branch:** `feature/vault-private-ai`  
**Base:** `main` at `182ecb430054f65e269558df779317e34cf0e015`

## Goal

Build a private local Vault that is useful immediately, even before Private AI is installed, then add persistent local semantic indexing and Granite-powered question answering without changing the Vault storage model.

The agreed product rule is:

> Upload/storage/extraction are core Vault capabilities. Private AI is an optional enhancement layer for semantic indexing and question answering.

The initial document formats are **PDF, DOCX, and TXT** only.

## Scope

### Included

- Real `/vault` document-management page.
- Real `/ai` **Ask your Vault** page.
- Multi-file local upload for PDF/DOCX/TXT.
- Private per-local-user file storage under the application data directory.
- SHA-256 duplicate detection.
- Local text extraction independent of AI readiness.
- Local document metadata and extracted text in SQLite.
- Document list with truthful extraction/indexing status.
- Open document through a main-process document ID lookup.
- Delete document with confirmation and full local cleanup.
- Retry failed extraction.
- Private AI seven-state setup model.
- User-triggered progressive download/verification/repair of llama.cpp + Granite + Nomic assets.
- Persistent chunking and Nomic embeddings.
- Automatic/background indexing when AI becomes ready.
- Retry failed indexing.
- Local Vault Q&A across all documents or a selected set.
- Granite answers grounded only in retrieved Vault chunks.
- Safe source excerpts returned to the renderer.
- Lazy local AI runtime startup.

### Excluded

- Images/OCR.
- Audio/Whisper ingestion.
- Cloud document upload or cloud-model fallback.
- Sharing Vault files with Circles.
- My Story or Family Tree as RAG sources.
- A dedicated external vector database.
- Remote sync/backup of Vault data.
- Document editing/version merging.

## Product boundaries

```text
Shared Circle data -> Jose's shared Circle API
Private Vault data -> local Windows machine only
```

Vault ownership is by the authenticated **local user**, not by the active Circle. Switching active Circles never changes the user's Vault.

No document bytes, extracted text, chunks, embeddings, prompts, or answers are sent to Jose's Circle API.

## Architecture

```text
Renderer
  |
  | safe business DTOs only
  v
Typed preload API
  |
  v
Electron main
  |
  +-- VaultService
  |    +-- VaultRepository -> SQLite
  |    +-- VaultFileStore -> private AppData files
  |    +-- DocumentExtractor -> PDF/DOCX/TXT
  |
  +-- OfflineAiService
  |    +-- asset manifest/download/verify/repair
  |    +-- embedding runtime (Nomic)
  |    +-- generation runtime (Granite)
  |
  +-- VaultIndexService
  |    +-- chunk extracted text
  |    +-- Nomic embeddings
  |    +-- persist Float32 vectors
  |
  +-- VaultQueryService
       +-- embed question
       +-- local similarity search
       +-- retrieve top chunks
       +-- Granite grounded answer
```

React never receives arbitrary source-file paths, SQLite paths, model paths, embedding vectors, localhost model endpoints, or process IDs.

## Local storage layout

Use Electron's application data directory as the root. Conceptually on Windows:

```text
%APPDATA%/Family Circle/
  family.db
  vault/
    users/
      <local-user-id>/
        documents/
          <generated-storage-name>.pdf
          <generated-storage-name>.docx
          <generated-storage-name>.txt
  offline-ai/
    bin/
      llama-.../
        llama-server.exe
        *.dll
    models/
      granite-4.0-h-micro-Q4_K_M.gguf
      nomic-embed-text-v1.5.Q4_K_M.gguf
```

Database rows store only a safe relative storage path. Renderer-facing DTOs never expose it. Stored filenames on disk are generated by main; the original user filename is metadata only and never used as an unvalidated path component.

## Upload and ingestion

The Electron main process owns file selection and storage. React never chooses arbitrary source/destination paths.

Recommended public operations:

```ts
vault.listDocuments()
vault.chooseAndUploadDocuments()
vault.onUploadProgress(listener)
vault.openDocument({ documentId })
vault.retryExtraction({ documentId })
vault.deleteDocument({ documentId })
```

`onUploadProgress` exposes only a generated upload/document handle, stage, percentage and safe message. It never exposes a filesystem path.

Upload flow per selected file:

```text
validate extension/type
  -> validate file size/safety
  -> SHA-256
  -> reject exact-byte duplicate for this local user
  -> copy into private Vault storage
  -> create document row
  -> extract text locally
  -> update word count + preview
  -> if AI ready: queue indexing
     else: waiting_for_ai
```

Initial safety limit: **50 MiB per document**, kept as a configurable main-process constant. This reflects the initial in-memory PDF/DOCX extraction implementation. Oversized files return a stable business error.

## Duplicate behavior

Duplicate identity is `(local_user_id, sha256)`.

- Same bytes uploaded again: do not make a second copy; return `already-exists`.
- Same filename but different bytes: keep both documents.
- Display-name collision is resolved locally, e.g. `Family History.pdf`, `Family History (2).pdf`.

Do **not** reproduce the legacy behavior of replacing the previous same-name document.

## Extraction

Initial extractors:

- PDF: local PDF parser.
- DOCX: Mammoth/raw-text extraction.
- TXT: UTF-8 text.

Extraction occurs without Granite or Nomic. A parser failure does not delete the stored file.

Failure state:

```text
Stored, but text could not be extracted
[Retry extraction]
```

Retry re-resolves ownership and the private source path in main.

## Open and delete security

Renderer sends only a safe document ID:

```ts
vault.openDocument({ documentId })
vault.deleteDocument({ documentId })
```

Main restores the protected local session, loads the row scoped to that local user, then resolves the private path.

Deletion is intentionally recoverable across the DB/filesystem boundary:

1. Resolve and verify `(documentId, localUserId)` while the row still exists.
2. Attempt source-file removal first. If it fails, keep DB metadata/chunks and return a stable retryable error.
3. After file removal succeeds (or the file is already absent), transactionally delete chunk rows and the document row.
4. If the DB transaction fails after file removal, the transaction rolls back and the remaining row acts as a cleanup tombstone; a retry detects the missing source file and completes DB cleanup.

This avoids silently dropping the only metadata needed to retry a failed filesystem deletion.

## Private AI state model

Reuse the seven-state model:

```text
not_installed
downloading
paused
verifying
ready
repair_required
failed
```

Private AI is optional. Vault upload remains enabled in every AI state.

AI setup is **user-triggered**; opening the app or uploading a document must never silently start a roughly 2 GB model download.

User-facing setup copy stays non-technical. GGUF, llama.cpp, model filenames, ports and endpoints remain in developer logs/docs.

## Private AI assets

Preserve Jose's proven local architecture:

- llama.cpp Windows runtime;
- IBM Granite 4.0 H Micro Q4 GGUF for generation;
- Nomic Embed Text v1.5 Q4 GGUF for embeddings.

Small-installer mode downloads verified assets later into AppData. A future/full-offline installer may bundle the same verified assets.

The bundled manifest—not renderer input—owns approved asset URLs/targets, expected sizes, SHA-256 hashes and extraction rules. Download into staging/temp, resume where feasible, verify before promotion, and never treat an unverified partial file as ready.

## Runtime process model

Do not start both AI servers because the desktop app launched.

Split runtime ownership conceptually:

```ts
ensureEmbeddingRuntime()
ensureGenerationRuntime()
```

- Indexing requires Nomic only.
- Question answering requires Nomic for the query vector and Granite for generation.

Processes are main-process owned, health-checked, hidden from the renderer, and stopped on app shutdown. Idle shutdown may be added after core behavior is stable.

## Indexing

```text
extracted document
  -> deterministic chunking
  -> Nomic document embeddings
  -> persist chunks + Float32 vectors
  -> mark indexed
```

Chunking is deterministic and versioned. Store `embedding_model` and `index_version` so a future model/chunking change can mark documents stale and reindex without touching source files.

Nomic task prefixes remain explicit:

```text
search_document: <chunk>
search_query: <question>
```

When Private AI becomes `ready`, the index service scans the **currently authenticated local user's** extracted documents whose index is missing/stale and indexes them in the background. On later app startup, if AI is already ready, the same scan resumes pending work.

Background jobs are always bound to the local user that queued them. Sign-out/cancellation must prevent results from being committed into another user's session context; DB writes remain explicitly scoped by local user/document ownership.

Index failure does not affect source/extraction health and can be retried.

## Query/retrieval

Public operation:

```ts
vault.ask({
  question,
  scope: { type: 'all' }
})
```

or:

```ts
vault.ask({
  question,
  scope: { type: 'documents', documentIds: [...] }
})
```

Main validates every selected document belongs to the protected local user.

Query flow:

```text
question
  -> ensure Nomic runtime
  -> Nomic query embedding
  -> cosine similarity against persisted chunk vectors
  -> top K chunks (initially 4-6)
  -> ensure Granite runtime
  -> grounded prompt with retrieved context only
  -> answer + safe source metadata
```

Stored chunks are **not re-embedded on every question**.

SQLite + in-process cosine similarity is sufficient for initial personal-Vault scale. Do not introduce FAISS/LanceDB/vector-server infrastructure until measurements justify it.

## Ask your Vault UI (`/ai`)

Initial scope options:

- All Vault documents.
- Selected Vault documents.

Do not add legacy `latest/current/story/combined` scope modes yet.

Example:

```text
Ask your Vault

What year did grandfather move to Kampala?

Search:
(*) All documents
( ) Selected documents

[Ask]
```

Answer:

```text
He moved to Kampala in 1978.

Sources
Family History.pdf
<relevant excerpt>
```

Renderer receives only safe answer/source data:

```ts
{
  answer: string,
  sources: [
    {
      documentId: string,
      fileName: string,
      excerpt: string,
      score?: number
    }
  ]
}
```

No stored path, vector, localhost endpoint, PID, model path or raw model response is public.

Granite's system instruction must require it to answer only from the supplied retrieved context and explicitly say the information was not found when context is insufficient. If no indexed content/relevant chunks exist, main short-circuits before Granite rather than asking the model to improvise.

## Error and recovery model

Renderer displays stable business outcomes only. Internal parser, SQLite, filesystem, localhost-runtime, model and stack-trace details remain in main logs.

Examples:

```text
Unsupported file type.
This file is too large for the current Vault limit.
This document is already in your Vault.
This document could not be extracted. Try again.
Private AI is not installed yet.
This document could not be indexed. Try again.
No searchable information was found in the selected documents.
Private AI could not start. Repair or retry setup.
```

## Security invariants

- Protected local session is restored in main for every Vault read/write/query.
- Renderer never supplies `localUserId`.
- Renderer never chooses destination paths.
- Renderer never receives storage/model/SQLite paths.
- Renderer never talks directly to localhost AI ports.
- File open/delete/retry is scoped by `(documentId, localUserId)` in main.
- Selected query document IDs are revalidated in main.
- Documents/text/chunks/embeddings/prompts/answers are never sent to the Circle service.
- No cloud LLM fallback.
- Raw model/parser/filesystem errors never cross the public desktop contract.
- AI asset URLs/targets/hashes come from the trusted main-process manifest, never renderer input.

## Delivery sequence

The architecture is one coherent design delivered back-to-back in three milestones.

### Milestone 1 — Real Vault

- migrations/repository;
- safe local file store;
- PDF/DOCX/TXT extraction;
- multi-file upload + safe progress;
- list/open/delete/retry extraction;
- real `/vault` UI;
- visible AI/index readiness without embeddings.

### Milestone 2 — Private AI + persistent indexing

- manifest/setup state;
- user-triggered download/verify/repair;
- split Nomic/Granite runtime lifecycle;
- deterministic versioned chunking;
- persisted Float32 embeddings;
- background/retry indexing.

### Milestone 3 — Local Vault Q&A

- real `/ai` page;
- all/selected-document scope;
- query embedding;
- local similarity retrieval;
- grounded Granite generation;
- safe source excerpts.

These milestones should be implemented back-to-back, without detouring into lower-priority Circle administration/tree features.

### Extraction

- PDF/DOCX/TXT success fixtures;
- unsupported/oversized rejection;
- extraction failure preserves source file;
- retry works;
- AI absence never blocks extraction.

### IPC/preload/boundaries

- business payloads only;
- malicious `localUserId`, arbitrary path, asset URL/target/model path/endpoint fields cannot affect main operations;
- no renderer filesystem/network/model-runtime access.

### Offline AI

- seven-state normalization;
- verified asset promotion only;
- interrupted/resumed setup;
- repair state;
- no automatic large download;
- embedding runtime can start without generation runtime.

### Indexing

- deterministic/versioned chunks;
- persisted vectors;
- waiting-for-AI -> indexing -> indexed;
- retry failed index;
- stale model/index version reindex;
- no query-time re-embedding of unchanged document chunks;
- user-scoped background writes across sign-out/session change.

### Query

- protected local-user scoping;
- selected document validation;
- top-K retrieval from persisted vectors;
- grounded prompt only;
- no-content short circuit;
- safe answer/source DTOs;
- internal endpoints never cross public contracts.

### Renderer

- Vault empty/list/upload/progress/duplicate/error states;
- open/delete confirmations;
- extraction/index retries;
- Private AI messaging never blocks upload;
- all/selected question scope;
- source rendering;
- no searchable content/AI unavailable states.
